# 経費・購入申請アプリ

TSS AI Coreの構想文書とは独立した、架空データ専用のローカル試作です。本番用ではありません。顧客の要望はユーザーを通じた代理情報であり、追加仕様の有効性は未検証です。

- リポジトリ： https://github.com/skaburagi-ui/expense-app

## 起動

Node.jsがあるPCで、このディレクトリに移動して実行します。依存パッケージの追加は不要です。

Windowsでは `start-local.cmd` をダブルクリックしても起動できます。

```powershell
npm start
```

ブラウザーで http://127.0.0.1:4173 を開きます。停止は Ctrl+C。動作検証は `npm test`。

## 試し方

1. 「社員」で新しい申請を作成。精算には架空の領収書画像またはPDFを添付します。
2. 「社長」に切り替え、申請を開いて承認。経理の事前受付はありません。
3. 「経理」に切り替え、承認済み申請を開いて処理完了を記録します。
4. 備品購入は購入前の承認後、社員が購入実績と領収書を登録します。承認額を超える場合は社長へ再申請します。
5. 差し戻しには理由が必要です。社員が修正すると社長の承認待ちに戻ります。
6. 購入前に価格や品目が変わったら「購入前に内容変更・再申請」を使います。再承認まで購入実績は登録できません。「購入を中止する」で終了にもできます。
7. 操作履歴の「その時点の内容」を開くと、操作・承認時の金額、用途、添付名と、変更前後を確認できます。添付の旧版データ本体は履歴には保存しません。

## 要件と仮の運用

- 伺った要件：10名程度、社内ネットワークのみ、PC・スマホ、社員→社長→経理、出張費精算・備品購入前申請。
- 試作で採用した案：精算時の領収書必須、増額時の再承認、経理からの差し戻しも社長へ再申請。お客様による確認は未実施です。
- 検証する仮説：経理の中継作業が減ること、社長が入力内容だけで判断できること、差し戻しによる往復が増えないこと。

## 制約

- 保存先はこのブラウザーのlocalStorageです。PC・スマホ・別ブラウザー間で共有されません。
- 役割切り替えは操作体験用で、ログインや権限制御ではありません。全申請を同じサンプル社員のものとして扱います。
- 実名・個人情報・実際の領収書を入力しないでください。送金・会計連携・正式な証憑保存は実装していません。
- 添付は画像またはPDF、1申請合計3MBまで。保存容量はブラウザー依存です。初期サンプルに添付はありません。
- 試作サーバーはPC内（127.0.0.1）だけで待ち受けます。社内LANへの公開、ファイアウォール変更は行っていません。
- スマホ幅の表示を確認できるレスポンシブ画面ですが、実機での社内Wi-Fi利用は未検証です。

本番化では共有サーバー・認証・権限・添付保管・バックアップ・社内LANの接続設定を別途設計し、社内での公開範囲を確認します。

## 次に確認・実装すること

1. 架空データでお客様に業務フローを確認いただき、購入前変更・再承認・差し戻しの運用案を確定する。
